  • TLS يساعد على حماية سرية البيانات وسلامتها، ويساعد العميل على التحقق من هوية الخادم.

السؤال الرئيسي — الدرس كله بيجاوب عليه
كيف يتواصل العميل والخادم لتشغيل تطبيق الويب، وما القواعد والرسائل التي يستخدمانها؟
”الفكرة الأساسية: تعمل تطبيقات الويب من خلال إرسال العميل للطلبات وإرجاع الخادم للاستجابات، باستخدام بروتوكولات (HTTP/HTTPS) وغالبًا واجهات برمجة تطبيقات تتبادل البيانات بصيغ مثل JSON.
الجزء الأول

1· العميل والخادم

العميل (client)
برنامج أو جهاز يرسل طلبًا إلى خدمة أخرى؛ ومن أمثلته متصفح الويب وتطبيق الهاتف. وهو الجانب الذي يطلب البيانات أو المعالجة.
الخادم (server)
الجانب الذي يستقبل الطلبات من العملاء، ويعالجها، ويعيد الاستجابات.
”تعتمد كثير من تطبيقات الويب على إرسال العميل طلبًا وإعادة الخادم استجابة.

الشكل 3.2.1 — اتصال العميل بالخادم
للفهمببساطة«عميل» و«خادم» مش أجهزة — دول أدوار. نفس الجهاز ممكن يكون عميل في موقف وخادم في موقف تاني. اللي بيحدد الدور هو: مين بيبعت الطلب ومين بيرد.

2· HTTP وHTTPS

HTTP (بروتوكول نقل النص التشعبي)
بروتوكول يستخدم لتبادل الرسائل بين عميل وخادم على الويب.
”HTTPS — استخدام HTTP عبر اتصال TLS (Transport Layer Security) آمن.
يساعد TLS على حماية سرية الاتصال وسلامته، وعلى مصادقة الخادم، بحيث لا يستطيع المتجسس قراءة المحتوى أو تعديله بسهولة أثناء النقل.
والمواقع التي تبدأ عناوينها بـ https:// تستخدم اتصال HTTPS.
للفهمطب ليه؟لأن الكلام في HTTP العادي بيمشي مكشوف. وعشان كده صفحة تسجيل الدخول لازم تكون HTTPS: إنت بتبعت كلمة مرور، وHTTP ما بيشفّرش المحتوى بنفسه — فاللي يقدر يعترض حركة الاتصال ممكن يقراها. وHTTPS بيحمي البيانات أثناء النقل باستخدام TLS. (الدرس 2-1 شرح آلية TLS نفسها بالتفصيل.)
الجزء الثاني

3· طلبات HTTP والاستجابات

”تتضمن الطلبات المرسلة من العميل إلى الخادم معلومات تسمى طريقة طلب HTTP توضح «نوع العملية المطلوبة».
الأسلوبالدورأمثلة
GETيُستخدم عادةً لطلب مورد أو بيانات من الخادمعرض صفحة ويب، استرجاع نتائج البحث
POSTيُستخدم عادةً لإرسال بيانات ليعالجها الخادمإرسال معلومات تسجيل الدخول، إرسال محتويات نموذج
طلب HTTP واحد، واستجابة مطابقة واحدة.
للفهمببساطةقاعدة تفرّق بينهم: GET بيُستخدم عادةً لما تطلب حاجة من الخادم، زي صفحة أو نتايج بحث. وPOST بيُستخدم عادةً لما تبعت بيانات عشان الخادم يعالجها، زي بيانات تسجيل الدخول أو نموذج. وخُد بالك من كلمة «عادةً» في التعريفين — الكتاب مابيقولش «دايمًا».

4· رموز الحالة

”تتضمن الاستجابات المرسلة من الخادم إلى العميل رقمًا يشير إلى نتيجة المعالجة، يسمى رمز حالة HTTP.
رمز الحالةالمعنى
200نجاح (تمت معالجة الطلب بنجاح)
404المورد المطلوب غير موجود بهذا العنوان
500خطأ داخلي في الخادم منعه من إكمال الطلب؛ ولا يحدد الرمز وحده السبب التفصيلي

للفهم — مش للحفظ

خُد بالك: وجود بيانات في الطلب لوحده مش بيخلّيه POST — ممكن رقم الجلوس يتبعت جوّه عنوان طلب GET لاسترجاع النتيجة. الطريقة بتعتمد على العملية وتصميم الموقع، وPOST بتُستخدم لإرسال بيانات يعالجها الخادم زي نموذج تسجيل.

للفهمطب ليه؟لأن الرقم بيقولك مين عنده المشكلة. 404 يعني الطلب وصل والخادم شغّال — بس العنوان غلط أو المورد مش موجود. أما 500 فمعناه المشكلة في الخادم نفسه — والكتاب بيحذّر: الرمز وحده ما بيحددش السبب التفصيلي.
الجزء الثالث

5· واجهة برمجة التطبيقات (API)

واجهة برمجة التطبيقات (API - Application Programming Interface)
مجموعة قواعد واضحة تسمح لبرنامج بطلب بيانات أو وظائف من برنامج آخر. وهي واجهة أو عقد محدد للتواصل بين البرمجيات.
وقد ترسل الواجهة الأمامية طلبات إلى خدمة خلفية عبر API وتستقبل منها البيانات.

6· صيغة JSON

”قد تعيد API بيانات بصيغة JSON (JavaScript Object Notation)، وهي صيغة نصية شائعة لتمثيل وتبادل البيانات المهيكلة باستخدام كائنات ومصفوفات وقيم بسيطة، وتدعمها لغات وأدوات برمجية كثيرة.
{
  "city": "Cairo",
  "temperature": 31
}
للفهمببساطةاقراها كده: كل سطر فيه مفتاح (key) وبعده نقطتين وبعدهم قيمة (value). هنا "city" مفتاح وقيمته "Cairo"، و"temperature" مفتاح وقيمته 31. لاحظ: القيمة النصية بين علامتي تنصيص، والرقم من غيرها. ودي بالظبط اللي نشاط «اقرأ البيانات» في الكتاب بيطلبها منك.
للفهمببساطة

التلاتة مع بعض في جملة: HTTP هو اللغة اللي بيتكلموا بيها · API هو العقد اللي بيحدد إيه المسموح تطلبه · JSON هو شكل البيانات اللي بترجع. تلات حاجات مختلفة — والامتحان بيحب يخلط بينهم.

الفكرة الرئيسة

يتواصل تطبيق الويب كتبادل منظم: يطلب العميل ويستجيب الخادم، باستخدام بروتوكول (HTTP/HTTPS)، وطريقة طلب HTTP (GET/POST)، ورمز حالة، وغالبًا واجهة برمجة تطبيقات تعيد البيانات بصيغة JSON.

خلي بالك من العبارات دي

  • GET «يُستخدم عادةً» لطلب مورد · وPOST «يُستخدم عادةً» لإرسال بيانات — يعني مش شرط دايمًا.
  • رمز 500: «ولا يحدد الرمز وحده السبب التفصيلي».
  • TLS يجعل المتجسس «لا يستطيع قراءة المحتوى أو تعديله بسهولة» — بسهولة، مش «مستحيل».
  • نموذج الطلب والاستجابة أساسي «مع وجود وسائل اتصال أخرى عند الحاجة».
  • «قد» تعيد API بيانات بصيغة JSON — يعني مش لازم.
  • في إجابة السؤال الرئيسي: «وقد تستخدم التطبيقات وسائل أخرى عند الحاجة».
للفهم

مثال من حياتنا

بتفتح موقع نتيجة الامتحانات. أول ما تكتب العنوان وتضغط إدخال: المتصفح (العميل) بيبعت طلب بأسلوب GET — «هات لي الصفحة دي». الخادم بيرد باستجابة ومعاها رمز حالة 200 يعني تمام.

بعدين بتكتب رقم جلوسك في الخانة وتدوس «بحث» — ده برضه طلب GET غالبًا، لأنك بتسترجع نتيجة، زي «استرجاع نتائج البحث» في جدول الكتاب. أما لو بتملى استمارة تسجيل وتدوس «إرسال»، فده POST عادةً، لأنك بتبعت بيانات عشان الخادم يعالجها.

ولو كتبت عنوان صفحة غلط هيرجّعلك 404 — الخادم شغّال، بس الصفحة مش موجودة. ولو الموقع نفسه فيه عطل، هتشوف 500.

وطول الوقت ده، لو الموقع بيبدأ بـ https:// يبقى الاتصال ماشي على TLS — رقم جلوسك مش ماشي مكشوف على الشبكة.

سؤال على نمط الامتحان — إجابة نموذجية

نموذج إجابة مقترح لسؤال الـ6 درجات

  1. العميل: المتصفح هو العميل — الجانب الذي يطلب البيانات أو المعالجة.
  1. الطلب: يرسل المتصفح طلبًا إلى الخادم عبر بروتوكول HTTP (أو HTTPS إذا كان الاتصال عبر TLS آمن).
  1. طريقة الطلب: يتضمن الطلب طريقة طلب HTTP توضح نوع العملية المطلوبة — وهنا GET لأنه يطلب موردًا (صفحة الويب).
  1. المعالجة: يستقبل الخادم الطلب ويعالجه.
  1. الاستجابة: يعيد الخادم استجابة تحتوي على المحتوى المطلوب.
  1. رمز الحالة: تتضمن الاستجابة رمز حالة HTTP يشير إلى نتيجة المعالجة — 200 عند النجاح، أو 404 إذا لم يكن المورد موجودًا، أو 500 عند خطأ داخلي في الخادم. ثم يعرض المتصفح الصفحة.
ركّز: التلميح سمّى خمسة عناصر بالاسم — العميل · الطلب · طريقة الطلب · الاستجابة · رمز الحالة. تأكّد إن الخمسة كلهم ظاهرين في إجابتك بالترتيب.

إجابة السؤال الرئيسي

السؤال
كيف يتواصل العميل والخادم لتشغيل تطبيق الويب، وما القواعد والرسائل التي يستخدمانها؟
”في كثير من الحالات يرسل العميل طلبًا ويعيد الخادم استجابة وفق قواعد HTTP، وقد تستخدم التطبيقات وسائل أخرى عند الحاجة. يحدد HTTP طريقة تبادل الرسائل، ويستخدم HTTPS اتصال TLS آمنًا. وتوضح طريقة HTTP الغرض من الطلب؛ فيستخدم GET عادةً لطلب مورد أو بيانات، وPOST لإرسال بيانات ليعالجها الخادم. وتبين رموز الحالة نتيجة معالجة الطلب. وقد تستخدم التطبيقات واجهة برمجة تطبيقات (API) وقواعد واضحة لتبادل البيانات، وربما تمثلها بصيغة JSON النصية المهيكلة.

مصطلحات أساسية

العميل – الجانب الذي يطلب البيانات أو المعالجة.
الخادم – الجانب الذي يعالج الطلبات ويعيد الاستجابات.
طريقة طلب HTTP – يوضح ما هو مطلوب (GET، POST).
رمز حالة HTTP – يبلغ عن النتيجة (200، 404، 500).
API – تتيح لبرمجيات مختلفة تبادل البيانات.
JSON – صيغة بيانات قابلة للقراءة.

الخلاصة في دقيقة

تذكّر: العميل يطلب، والخادم يستجيب – عبر HTTP/HTTPS، بأسلوب (GET/POST)، ورمز حالة، وغالبًا واجهة برمجة تطبيقات تعيد بيانات JSON.

  • العميل يطلب · الخادم يستجيب — والأدوار مش أجهزة.
  • API: قواعد تسمح لبرنامج بطلب بيانات أو وظائف من آخر · JSON: صيغة نصية للبيانات المهيكلة.
  • HTTP: بروتوكول تبادل الرسائل · HTTPS: نفسه عبر TLS آمن.
  • رمز الحالة: 200 نجاح · 404 المورد غير موجود · 500 خطأ داخلي في الخادم (ولا يحدد السبب التفصيلي).
  • التحفّظ: نموذج الطلب والاستجابة أساسي مع وجود وسائل اتصال أخرى عند الحاجة.

اتأكد إنك قادر على

  • أعرف تعريف العميل والخادم وأمثلة على كل واحد.
  • أعرف GET وPOST وأقدر أصنّف أي إجراء عليهم.
  • أعرف API وJSON ومابلخبطش بينهم.
  • أقدر أشرح خطوة بخطوة رحلة طلب صفحة ويب.
  • أفرّق بين HTTP وHTTPS وأعرف دور TLS.
  • أحفظ التلات رموز ومعناها، وأعرف إن 500 ما بيحددش السبب التفصيلي.
  • أقدر أقرا مفتاح وقيمة من مقطع JSON.

01 · طبّق ما تعلمته — خدمة الطقس

تقدم خدمة الطقس واجهة برمجة تطبيقات تعيد توقعات اليوم عندما يرسل العميل طلبًا. باستخدام ما تعلمته، اذكر طريقة طلب HTTP التي سيستخدمها العميل لاسترجاع التوقعات، ولماذا يجب أن تستخدم الخدمة HTTPS. ووضّح ميزة واحدة لاستقبال البيانات بصيغة JSON.

عناصر الإجابة الأسلوب + سببه · سبب HTTPS مربوط بحماية الاتصال · ميزة واحدة لـJSON من تعريف الكتاب.

02 · فكّر كمهندس — ابحث ثم قرر

تريد مدرسة في مدينتك تطبيق ويب يسجّل فيه الطلاب الدخول، ويعرضون جدولهم الدراسي، ويحمّلون ملف PDF. أنت تخطط لكيفية تواصل العميل والخادم.

(1) اختر الأسلوب. لثلاثة إجراءات، حدد ما إذا كان GET أو POST هو الأنسب، وبالنسبة للإجراء الأخير حدد ما إذا كانت واجهة برمجة تطبيقات متضمنة.

(2) اختر البروتوكول. حدد ما إذا كان يجب أن يستخدم تسجيل الدخول HTTP أو HTTPS، واذكر السبب.

(3) قرّر. أوصِ بتصميم الاتصال واذكر سببين. في أزواج، قارنوا اختياراتكم للأسلوب واتفقوا معًا على الإجراء الذي يجب أن يستخدم POST.
